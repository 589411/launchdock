## 🧭 依判讀框架決定的下一步

### 1. 最大機會缺口：cli-guide（4,136 曝光、CTR 0.7%）

它一頁就吃掉全站 12% 的曝光，但 CTR 是 Top 10 裡最低。排名 7.6 已在第一頁——**人到了門口沒進來，是門面問題**。

對照贏家的標題公式，差別很清楚：

| | 標題後半段 |
|---|---|
| ✅ caffeinate（CTR 6.3%） | 「讓 Mac 不睡、**AI Agent 整夜不斷線**（含怎麼停止）」← 具體場景＋可帶走的結果 |
| ⚠️ cli-guide（CTR 0.7%） | 「命令列介面（Command-Line Interface）**白話完整介紹**」← 同義詞重複＋自我描述 |

「是什麼？」這個前半兩者都有；**真正拉開 CTR 的是後半有沒有給讀者「我會得到什麼」**。
建議改法（保留 SEO 主詞，換掉後半）：
> 「CLI 是什麼？從零看懂命令列：跟 GUI／終端機／Shell 差在哪（附 10 個必學指令）」

有比較、有數字、有可帶走的清單。若 CTR 從 0.7% 拉到 3%（仍遠低於站上 9% 天花板），就是 **+90 點擊／28 天**。

⚠️ 但要有預期：`cli` 是**意圖極雜的字**（很多人在找特定工具的 CLI），CTR 天花板本來就比 `caffeinate` 這種明確指令名低。

### 2. 判讀框架要補一格：「曝光↑但排名 >20」

`api key`（排名 25.7）與 `google api key`（排名 45.2）曝光都在漲，CTR 卻是 0%。
**第 3～5 頁的頁面，改標題完全無效**——沒人翻到那裡去看你的標題。原框架沒有這一格，補上：

| after 相對 before | 判讀 | 下一步 |
|---|---|---|
| **曝光 ↑、CTR 0%、排名 > 20** | 🔻 不是門面問題，是**還沒排進視線** | 改標題無效。要嘛補內容深度＋內鏈（拉排名），要嘛承認那是超競爭字、把力氣移去長尾 |

`api key` / `google api key` 是全球性超競爭字，建議**不投資**，改攻已證明有效的長尾（`ollama cloud api key` 已經 2 點擊 / 122 曝光 / 排名 8.6）。

### 3. github developer settings：可能已到天花板

652 曝光、排名 7.6（第一頁）、CTR 只 0.2%。標題「GitHub Developer settings 在哪？」已經正面對準查詢意圖了。
合理推論：**搜這個字的人絕大多數是想直接跳到 github.com 的設定頁，不是想讀教學**。這種「導航型查詢」的第三方頁 CTR 天花板本來就極低。
➡️ 建議**最多再改一次文案就停**（例如強調「Fine-grained Token 怎麼選、passkey 二次驗證」這種官方頁不會給的東西），不要無限投資。

### 4. 複製成功公式（優先序）

caffeinate 與 openrouter 驗證了公式：**「主詞 + 是什麼/怎麼做」＋「具體場景或可帶走的結果」＋「（括號補充：含免費／含怎麼停止／附 N 個…）」**。
套用順序＝按「曝光高 × CTR 低 × 排名 ≤10」排：
1. **cli-guide**（4,136 曝光 / 0.7% / 7.6）← 最高優先
2. `dev-cli-tools-mac`（478 曝光 / 2.9% / 8.0）
3. `en/grok-connect-github`（521 曝光 / 3.3% / 6.7）— 英文版文案也值得比照調

### 5. FAQ／schema：**零效果，但錯不在標記——建議停止投資 rich result**

**觀測（Joseph 2026-08-10 手動點開 GSC「搜尋外觀」分頁）**：**完全「無資料」**——沒有任何搜尋外觀類型
的曝光，常見問題列、精選摘要等豐富結果一列都沒有。

**但 schema 本身是好的。**同日驗證線上首頁（`curl` 抓 HTML 後解析 JSON-LD）：

```
找到 1 個 JSON-LD 區塊
[1] @type=FAQPage  @context=OK
    mainEntity 題數: 8
    結構完整性: ✅ 每題都有 Question.name + acceptedAnswer.text
```

⇒ **不是標記壞掉、也不是 `home-faq.ts` 那套資料驅動生成有問題**（它確實有正確 `.map()` 出 8 題）。

**最可能的原因是 Google 的政策，不是我們的實作**：Google 自 2023 年 8 月起大幅限縮 FAQ 豐富結果，
**只對「知名的政府與醫療類權威網站」顯示常見問題版位**，一般網站即使標記 100% 正確也不會拿到那個版位。
若這條政策在 2026 年仍維持（**請以 Google Search Central 的 FAQ structured data 文件現況為準，別只信本文**），
那「搜尋外觀無資料」就是**預期行為，不是待修的 bug**。

**要區分「Google 沒解析到」vs「解析到但不給版位」**，用 GSC 的**網址審查**查首頁，看
「已偵測到的項目」有沒有列出「常見問題」：
- **有列出** → Google 解析成功、只是不給版位 ⇒ **確認是政策問題，停止投資 rich result**。
- **沒列出** → 那才是技術問題（但依上面的 HTML 驗證，機率低）。

**➡️ FAQ 的價值要重新定位**（不要因為沒 rich result 就拆掉）：
1. **給 AI 搜尋／LLM 讀**——這條線和站上既有的 `llms.txt` + 全站 `.md` 端點是同一個投資方向，比 rich result 更值得押。
2. 首頁內容本身的可讀性與內部連結（FAQ 每則都指向對應文章）。
3. 政策若哪天放寬，標記已經備好。

**釐清一個容易誤歸因的數字**：首頁表現不錯（18 點擊 / 140 曝光 / CTR 12.9% / 排名 3.8），
但那是品牌字帶的（`藍鴨` 13.1%、`launchdock` **38.5%**），**與 FAQ 無關**。

## 一句話結論

**量：大成功**（日均點擊 ×2.4、曝光 ×2.8，但要扣掉索引修正與視窗重疊的貢獻）。
**質：一半成功**——caffeinate 與 openrouter 證明標題公式有效；但最大流量入口 `cli-guide` 的門還沒被打開，而 `api key` 系列則是排名根本沒進視線、改文案無用。
**FAQ／schema：零效果，但錯不在標記**（標記驗證通過，最可能是 Google 只給政府/醫療 FAQ 版位）
→ **停止投資 rich result，把 FAQ 的價值改押在 AI 搜尋／`llms.txt` 那條線。**
**下一步只做一件事**：改 `cli-guide` 的標題後半段，兩週後單看它的 CTR。
