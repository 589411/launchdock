## 現場流程

1. **開場前**：講師端 → 輸入課程名稱 → 「建立場次」→ 拿到 6 碼代碼 → 投影代碼＋QR。
2. **暖身**：點 `Q0 你今天是線上還是實體參加？`
   —— **同時測通投票系統 + 點名**，一石二鳥。數字對得起來就可以開始。
3. **每一題的節奏**（投票是**課程中間停下來的互動**，不是問卷）：
   ```
   跑完該段的 Colab，螢幕出現一個數字
     → 講師端點該題（如 Q3）
     → 口頭喊「請重新整理」   ← ⭐ 學員端不會自己跳，這一步不能省
     → 30 秒後看分布
     → 按「⏸ 停下來討論」  ← 學員端收起選項，改顯示討論題，全班停在同一個問題上
     → 挑極端值邀請分享（可以拒絕）
     → 下一段再出下一題
   ```
   **學員一次只看得到一題**——出哪題就只有哪題，其他七題完全不出現，
   也不會有人先跑到最後一題去。畫面最上面標明「Day 3 · 段 2 · N1 商品關聯」，
   學員一眼知道自己在課程的哪一段。

   > ⏸「停下來討論」**只是畫面狀態，不動場次 status**——按下去不會有任何人送出失敗，
   > 晚到的人也還投得進來。跟下面那條紅線是兩回事。
4. **投影模式**：右上角「🖥 投影模式」把題目和長條圖放大、把講師提詞收起來（**提詞不會被學員看到**）。
5. **下課**：什麼都不用按。⛔ **不要去關場次**（見紅線）。

## ⛔ 紅線：不要去按「結束收件」

投票的權限規則是 `WITH CHECK is_quiz_session_open(session_id)`，**只認 `status='open'`**。

Poll 模式**整堂課都在收件**——中途誤按一次「結束收件」，全班從那一刻起投什麼都失敗。

所以 `/admin/poll-live/` **故意沒有這顆鈕**。那顆鈕只在 `/admin/quiz-live/`。
上課那天**不要開 quiz-live 那一頁**。

若學員說投不了：先看講師端有沒有紅色橫幅（「這個場次是關閉狀態」）→ 去 quiz-live 按「▶️ 重新開放」。

## 三層備案（沒人願意分享時）

| 層 | 觸發 | 做法 |
|---|---|---|
| 1 | 沒人開麥 | 講師端**匿名留言牆**（學員選填的一句話）直接念出來 |
| 2 | 連文字都沒有 | 念講師提詞裡的**跨業態對照表**（每題都備好了） |
| 3 | 完全冷場 | 直接進下一段。**截圖進手冊，不強求** |

> **冷場不是失敗。冷場的時候，你就是那個第一個分享的人。**
> 第一題**一定要由講師先示範一次**，示範格式和長度。有樣本才有人敢跟。

**🔌 全系統掛掉的備案**：退回 Google 表單（同樣八題同樣選項），Colab 畫圖。
Day 3 建議兩條並行，Day 4 才全押站上版本。

## 常見狀況

| 狀況 | 原因 / 處理 |
|---|---|
| 學員說「還是舊的題目」 | **學員端不會自動更新**（刻意的，省 75 萬次請求）。請他按頁面上的「🔄 換題了？點我更新」。 |
| 學員晚到／中途加入 | 學員端下半部列了**全部八題**，可以自己往下投，不會卡住。 |
| 有人想改答案 | 直接改點別的選項就好。同一人同一題**看最後一次**。 |
| 分布數字比人數少 | 沒按更新的人還沒投。喊第二次「請重新整理」。 |
| 想問臨時想到的問題 | 講師端「✏️ 臨時想問別的」→ 打題目＋一行一個選項 → 「出這題」。 |
| 想看哪一行的人怎麼投 | 勾「業態交叉表」→ 業態 × 選項的矩陣。**這是這八題的教學核心。** |
| 學員找不到自己的行業 | 業態有 14 個常見類別（含**傳產／製造**、批發貿易 B2B、醫療、補教、旅宿、汽機車、建材五金），找不到就點「✏️ 其他（自己打）」自己輸入，交叉表上會直接顯示他打的行業名。 |
| 學員問「為什麼要選業態」 | 整堂課只問一次。跨業態對照是這八題的核心——同一個問題，超市和家具業的答案差 60 倍，那個落差就是最有價值的部分。 |

## 隱私設計（學員問起時可以直接講）

- 全匿名：只存瀏覽器產生的隨機 `participant_id`，**不存姓名、email、帳號**。
  業態是自己選的，不是身分。
- 匿名身分**只能投票，不能讀取任何人的票**，也**改不了、刪不了**別人的票（實測驗過）。
- 場次代碼**不可被列舉**。
- 講師端只呈現聚合數字與匿名留言，**可以安全投影**。

## 技術現況（給 AI agent）

| 項目 | 位置 |
|---|---|
| 資料表 | `poll_responses`（migration `016_create_class_polls.sql`），共用 `quiz_sessions` |
| 現在投影哪一題 | `quiz_sessions.poll_active` JSONB，整題存進去（題號＋題目＋選項＋`segment` 課程段落＋`discuss` 討論題＋`locked` 討論中） |
| 題庫（唯一策展點） | `src/data/class-poll.ts` |
| 學員端 | `src/components/ClassPoll.tsx` → `/poll/` |
| 講師端 | `src/components/PollLiveDashboard.tsx` → `/admin/poll-live/` |
| 對齊檢查 | `npm run poll:check`（對撞 `sunlit-retail-sim/wp9-colab/handouts/day{3,4}-學員講義-v2.md`） |

**為什麼不塞進 `quiz_responses`**：那張表的 schema 硬綁 AI 能力測驗
（`scores` / `primary_level` / `gap_dimension` 都 NOT NULL），參數題沒有分數也沒有等級，
硬塞後台數字會變垃圾。所以開姊妹表。

**為什麼學員端不即時**：即時是投影給全班看的，不是給學員看的。
學員端也輪詢的話，一堂課 75 萬次請求。講師口頭喊一聲就解決——**這一刀砍掉 90% 複雜度。**
